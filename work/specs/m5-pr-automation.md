# Phase 5.11: PR Automation & Remote Push

**Milestone**: M5 — Autonomous Intelligence
**Status**: Design Spec
**Dependencies**: 5.0 (WebSocket for real-time status), 5.2 (semantic merge resolution)
**Wave**: 3 (alongside 5.8, 5.10)

## Problem Statement

Today the agent workflow ends at local merge:

```
CURRENT:
  agent works → commits in worktree → squash merge to local main → STOP

  Missing:
  - No push to remote
  - No PR creation
  - No CI/CD feedback loop
  - No GitHub-native review trail
  - No branch protection awareness
  - Commits not enforced to be atomic
```

This means all work is invisible to the team until a human manually pushes and creates a PR. For a "zero-touch" system (M5's goal), the last mile is missing.

## Proposed Architecture

```
NEW (full cycle):

Agent works in worktree branch (pilot/<taskId>)
  ↓
Small atomic commits (enforced)
  ↓
On task completion:
  1. Push branch to remote (git push -u origin pilot/<taskId>)
  2. Create PR via gh cli (structured body)
  3. CI runs (GitHub Actions / checks)
  4. PM reviews diff internally (existing pm-decisions.reviewDiff)
  5. If checks pass + PM approves → auto-merge PR
  6. If checks fail → escalate (existing escalation engine)
  7. Cleanup: delete remote branch after merge
```

## Design Principles

1. **Opt-in by default** — `policy.yaml` controls whether PRs are created or just local merge
2. **No force push** — branch is push-only, never force-pushed
3. **Structured PR body** — plan steps, test results, cost, files changed
4. **Existing tools** — uses `gh` CLI (GitHub's official tool), no custom API clients
5. **Fallback graceful** — if `gh` not installed or no remote, falls back to local merge (current behavior)
6. **Works with branch protection** — respects required reviewers, status checks

### 3. Commit Atomicity Enforcement

Before PR creation, validate commit quality:

```
Rules:
  - Each commit must reference bd task ID (existing convention)
  - No commit > 500 lines changed (configurable)
  - No commit with mixed concerns (feat + fix in same commit)
  - Conventional commit format enforced (not just documented)
  - If violations found: warn but don't block (configurable to block)
```

### 4. Policy Configuration

```yaml
# policy.yaml additions
github:
  enabled: false                    # opt-in
  pr_on_complete: true              # create PR when task completes
  auto_merge: false                 # auto-merge when checks pass + PM approves
  auto_push: true                   # push branch to remote
  merge_strategy: "squash"          # squash | merge | rebase
  delete_branch_after_merge: true
  pr_template: "default"            # or path to custom template
  require_checks_pass: true         # wait for CI before merge
  commit_enforcement:
    max_lines_per_commit: 500
    require_conventional: true
    block_on_violation: false       # warn vs block
  labels:
    - "pilot-agi"
    - "auto-generated"
  reviewers: []                     # GitHub usernames (empty = no required reviewers)
  base_branch: "main"              # target branch for PRs
```

### 5. Integration Points

#### PM Daemon (`pm-daemon.js`)
- After successful worktree merge, call `prAutomation.pushBranch()` + `createPR()`
- New scan: `_prStatusScan()` — check open PRs for passed checks, trigger merge
- On merge failure → route to escalation engine

#### Worktree (`worktree.js`)
- `mergeWorktree()` gains optional `pushAfterMerge` parameter
- Actually: DON'T merge to local main first. Push the worktree branch directly.
- New flow: worktree branch → push → PR → GitHub merges to main

#### Agent Loop
- On task complete, agent calls `prAutomation.pushBranch()` if github.enabled
- Agent doesn't merge locally — just pushes and reports PR URL
- PM daemon handles the rest (status check, merge)

#### Escalation (`escalation.js`)
- New event type: `pr_check_failure` — CI checks failed on PR
- New event type: `pr_merge_conflict` — PR has merge conflicts with base
- Escalation path: retry CI → rebase → escalate to human

#### Notification (`notification channels`)
- PR created → notify configured channels (Slack/Discord/Telegram)
- PR merged → notify with summary
- PR failed checks → notify with failure details

## Flow Diagram

```
Task Complete
  │
  ├─ github.enabled: false → local merge (current behavior, unchanged)
  │
  └─ github.enabled: true
       │
       ├─ 1. Validate commits (atomicity check)
       │    └─ violations? → warn/block per policy
       │
       ├─ 2. Push branch: git push -u origin pilot/<taskId>
       │    └─ fail? → retry once → escalate
       │
       ├─ 3. Create PR: gh pr create --base main --head pilot/<taskId>
       │    └─ fail? → check if PR exists → escalate
       │
       ├─ 4. Wait for CI checks (pm-daemon polls or webhook)
       │    └─ fail? → escalate (pr_check_failure event)
       │
       ├─ 5. PM internal review (existing reviewDiff)
       │    └─ reject? → agent fixes → force push update
       │
       ├─ 6. Auto-merge (if policy allows)
       │    └─ conflict? → rebase → escalate (pr_merge_conflict)
       │
       └─ 7. Cleanup: delete remote branch
```

## Edge Cases

1. **No `gh` CLI** — detect on startup, disable github features, warn user
2. **No remote configured** — `git remote -v` empty → fall back to local merge
3. **Auth failure** — `gh auth status` check on startup
4. **PR already exists** — find existing PR for branch, update instead of create
5. **Base branch diverged** — rebase worktree branch before push
6. **Multiple agents same repo** — each has unique branch, no conflicts
7. **Rate limiting** — GitHub API rate limits → exponential backoff
8. **Large PRs** — warn if PR > 1000 lines, suggest decomposition

## Success Criteria

- [ ] `github.enabled: true` → task completion creates PR on GitHub
- [ ] PR body contains plan steps, test results, cost summary
- [ ] CI checks monitored; failures escalated within 60s
- [ ] Auto-merge works when checks pass + PM approves
- [ ] Branch cleanup after merge (no stale remote branches)
- [ ] Commit atomicity violations detected and reported
- [ ] Fallback to local merge when GitHub unavailable
- [ ] Works with branch protection rules (required reviewers, status checks)
